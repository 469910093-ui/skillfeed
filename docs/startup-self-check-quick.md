# 创业自检报告 - 快速版：skill-feed（Skills 版抖音）

> 基于 startup-self-check 快速版；输入来自当前产品决策与实网 refresh 证据。  
> 日期：2026-07-27

## 整体健康度评分

**58 / 100** — 方向清晰，但「供给饥荒 + 上下文未接通 + 反馈真空」会让 MVP 看起来像空壳。

## 各维度分布

| 维度 | 分 | 条 |
|---|---|---|
| 产品-市场匹配度 | 55 | 痛点真实（skill 太多找不到/装不对），但「刷 Feed 找远程 skill」尚未被外部用户验证 |
| 商业模式健康度 | 40 | 本地工具、无付费；OK 作工具，融资叙事弱（本阶段可不追求） |
| 团队与执行力 | 75 | 已有 skill-picker 引擎可复用；一周内可砍安装、加双源、加反馈 |
| 营销与增长 | 50 | 可借 HelloGitHub Skills 专栏叙事；Trending  alone 无法稳定获客内容 |
| 风险与合规 | 70 | 只链到 GitHub、不代装，安全面可控；爬虫/API 限额与 HTML 改版是运维风险 |

## Top 3 风险点（最易翻车）

1. **源头饥荒（供给）**  
   实网：仅 `github.com/trending` 时常 **0 个 skill 形仓库** → Feed 空 = 产品死亡。  
   → **立即行动**：双源——Trending（热度）+ HelloGitHub Skills / GitHub Search `SKILL.md`（稳定供给）；卡片标明 `source`。

2. **上下文未接通（推荐不准）**  
   当前 G_rel = 本机 catalog 兴趣画像，≠ 会话当下意图。用户会觉得「推荐的和我正在做的无关」。  
   → **立即行动**：MVP 增加「意图输入框」作为查询侧；Phase 2 接会话摘要；每卡强制 `why` 可解释。

3. **反馈真空（无法迭代门槛）**  
   无 click/有用/不准 信号 → min_stars/min_rel 只能拍脑袋。  
   → **立即行动**：本地 `feedback.jsonl`（有用/不准/打开 GitHub）；周报调门槛档位。

## 已对齐的正确决策

- **只推荐到 GitHub，不参与安装** — 降低安全/支持成本，边界清晰（与 skill-picker 拆线）。
- **与 skill-picker 拆产品线** — 保住「100% 本地」承诺。
- **门禁可配置** — 方向对；缺「宽松/标准/严格」档位与空 Feed 解释。

## 2 周改进后预期

聚焦双源 + 意图框 + 反馈落盘 → 健康度可到 **75+**；空 Feed 率应显著下降，推荐可解释率接近 100%。
