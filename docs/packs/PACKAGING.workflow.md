# 场景包装配工作流

每次要把散落的 Skill 收成**可卖场景包**，都走这一页。  
Agent 入口：项目 skill `packaging-scene-skills`。  
下游契约：`HOWTO.contract.md`（用户怎么学）、`QUALITY.contract.md`（能不能卖）。  
场景真相源：`docs/PRD.md` §3.1。

卖的是「某类人 + 一条可跑工作流 + 最少 Skill」，不是小红书原文，也不是 awesome 清单。

## 0. 和另外两套管线的边界

| 管线 | 产物 | 何时走 |
|---|---|---|
| 资源清单底表 | 飞书「资源清单」全量行 | 爬到 GitHub/笔记就入库，不论是否 skill |
| 本工作流（场景包） | `包-总览` + `包-{场景}` | 要按人群/岗位组装解决方案 |
| 商品包 | `docs/packs/<sku>/HOWTO.md` + `drills/` + `pack.yaml` | 候选包要卖、要给冷用户装 |

禁止：把底表行直接当场景包；把场景包行直接当已上架 SKU。

## 1. 锁场景

只认 PRD §3.1 这八个。对不上 → **先改 PRD 再拆表**，禁止口头新造。

| 大类 | 场景 | 卖给谁 | 工作流主线才算齐 |
|---|---|---|---|
| 电商 | 货架电商 | 淘宝/京东/拼多多店主 | 主图→详情→文案→上架→店铺复盘 |
| 电商 | 跨境电商 | 亚马逊/多平台卖家 | 选品→供应链→Listing→广告→利润 |
| 电商 | 内容电商 | TK/小红书带货 | 调研→拆对标→Hook→内容→案例库 |
| 电商 | 直播电商 | 主播/中控 | 货盘→话术→开播→场控复盘 |
| 自媒体 | 资讯类自媒体 | 公众号/博客/独立站 | 选题→长文→SEO/GEO→日历 |
| 自媒体 | 短剧 | 编导/切片分发 | 选题→分镜→成片→分发 |
| 自媒体 | 营销广告自媒体 | 投放/品牌/增长 | 地基→文案→广告→SEO/AEO→CRO |
| 自媒体 | 平面设计自媒体 | 美工/封面设计 | 风格→主图→详情→封面海报 |

一次作业锁定 **一个场景**（补采）或 **总览+缺的子表**（扩场景）。不要把财务/选品等新词偷偷塞进现有表冒充新包。

## 2. 采集

目标：找到「一篇里点了好几个 Skill、并且能嵌进某条工作流」的笔记。单点安利降权。

1. 用 `web-collection` 按用户指定平台 + 关键词跑。  
2. 关键词必须 UTF-8 直发（Python 调 connector JSON）。**禁止** bash `--keyword` 传中文。  
3. 10 分钟 `recordCount` / 已采条数不涨 → 按仓库规则停掉重启当前词；同一词最多 5 次，第 5 次失败就记卡点并往下。  
4. 读正文，不要下载一堆不明附件。  
5. 落盘目录：`~/.skill-feed/web-collection-runs/`，每词一份 catalog JSON（标题/作者/链接/正文/抽到的 Skill 名）。

底表入库（GitHub 校验、星数、SKILL.md）仍走：

```text
python scripts/xhs_bitable_loop.py run --note-link-limit 8
python scripts/xhs_bitable_loop.py audit-stars
```

那是资源清单使命，**不能代替**第 4–5 步的场景表。

## 3. 本地编目

对 catalog 只做三件事：

1. 留下「n≥3 个可识别 Skill」或「写清 SOP 主线」的笔记。  
2. 按锁定场景归堆；一篇笔记可以进多个场景，但每行必须改写变现卡点，禁止复制粘贴同一句。  
3. **不要**把 50 条原笔记写成产品表。

## 4. 抽包打标

每一行填满这些槽，缺一格就还没抽完：

| 槽 | 写什么 |
|---|---|
| 场景细分 | 工作流上的一截，如「详情页结构」「视频前三秒」 |
| 变现卡点 | 用户愿付钱的那句痛，不用内部黑话 |
| 工作流 | 这一步的前后件，能接上主线 |
| 打包优先级 | 核心必装 / 增强 / 待补 |
| Skill名称 | 正文里的原名；没有就 `待补采：…` 或「…（笔记未点名）」 |
| 这个Skill干什么 | 人话，对应该卡点 |
| 出处 | 作者 + 笔记标题 |
| 链接 | 原笔记 URL |
| 材料完整度 | 见下表 |

### 材料完整度（铁律）

| 值 | 判定 |
|---|---|
| 正文点名 | 正文出现 Skill 名或仓库名 |
| 仅流程 | 有顺序/套装数量，没有名单 |
| 可借用 | 别的场景已点名，本场景能复用；出处必须写清来源场景 |
| 待补采 | 主线需要、材料没有 |

未点名 **不得**写成已验证能力。标题「17 个 / 20 个」而正文没名单 → 只能「仅流程」。  
直播、短剧这类经常没材料：先立骨架、标 P1，禁止标「可卖·材料齐」。

默认安装只收「核心必装 ∩ 正文点名」。增强和待补不进默认 `pack.yaml`。

## 5. 写入飞书

策展 Base（可进代码，不是密钥）：`PCWZbMvydabY2Xs1yYSc2sc7nth`

| 表名 | 用途 |
|---|---|
| `包-总览` | 八包各一行：卖点、主线、点数、完整度、P0/P1 |
| `包-货架电商` 等 | 该场景的 Skill 行 |

总览「材料完整度」只准三值：`可卖·材料齐` / `可卖·需补名` / `骨架·待补采`。  
打磨优先级：P0 = 可以往商品包推进；P1 = 只准补采，不准上付款页。

`lark-cli` 必须走 `base` 子命令（不是 `bitable`），并加 `--as user`。可复用：

`~/.skill-feed/web-collection-runs/push_scene_sheets.py`

改表后用中文回报：新建/覆盖了哪些表、各多少行、哪些仍是骨架。禁止说「已刷新成功」却 0 条变化。

## 6. 交给商品包（可选，用户点名才做）

飞书齐了 = 候选。要变成用户能装的包：

1. 每个默认 Skill 能钉到 GitHub commit，或标为自研薄 Skill。合集仓 / awesome 不准进商品。  
2. 按 `HOWTO.contract.md` 写固定八节 + 至少三份 `drills/`。  
3. 按 `QUALITY.contract.md` 过 P0–P4。P1 冷用户没绿 → 只标候选。  
4. 样板抄 `docs/packs/life-work/`。新 SKU 目录：`docs/packs/<sku>/`。

P1 失败先改手册和例句，**不要加 Skill**。P0 缺 Part 就自研或砍 SKU，禁止用无关 Skill 填数。

## 7. 一次作业的完成定义

- [ ] 场景锁在 §3.1，新场景已回写 PRD §13  
- [ ] catalog 在本地，能指出「多 Skill 笔记」有哪些  
- [ ] 飞书总览该行数字与子表一致  
- [ ] 每一行有完整度；没有「看起来像名字、实际是标题切词」  
- [ ] 骨架包已用中文点明缺哪段工作流、建议补采哪些词  
- [ ] 若用户要卖：HOWTO + drills 齐，否则到飞书候选为止  

## 8. 红线

- 把原文笔记当产品交付  
- 编造 Skill 名或仓库名  
- 新场景不改 PRD  
- 采集卡死超过 10 分钟还空转  
- 场景包装配和资源清单底表互相覆盖  
- 直播/短剧材料不够却标可卖
