# 场景包操作手册契约

每个可售卖包装完后，用户打开的第一份东西必须是 `HOWTO.md`。
**八节标题固定**，换包不换学法。节可以写短，不能缺、不能改名。

Agent 装包后、做任何 Part 之前，先读这份手册。用户说「这个包装好了怎么用」，
也只准按手册带练，不准改口成命令行课。

## 固定八节

| # | 标题（原文照抄） | 写什么 | 禁止 |
|---|---|---|---|
| 1 | 这个包帮你完成什么 | 一句话岗位问题 | 内部 scene id、仓库名堆砌 |
| 2 | 今天先做哪一件 | 10 分钟第一胜 + 一句可复制的话 + 指向 `drills/01-*` | 「请先浏览全部 Skill」 |
| 3 | 怎么对 Agent 说话 | 4–6 句人话例句 | `skillpick`、`--yes`、API 名当主路径 |
| 4 | 材料放哪 | 三个文件夹：`纪要/` `待办/` `本周/` | 让用户自己想目录结构 |
| 5 | 每个 Part 何时用 | 对照表：何时开口、成功长什么样 | 原理、模型名、评分公式 |
| 6 | 不要做的事 | 至少四条红线 | 空泛的「请谨慎」 |
| 7 | 第二天才能接的手 | 0 或 1 个 MCP；可整节写「跳过」 | 五个账号一起开 |
| 8 | 坏了怎么办 | 三个最常见卡点，各三步 | 丢去外部文档站 |

## 必须附带的练习

`drills/` 至少三份可改字就跑通的样例：

1. `01-*` — 对应第 2 节第一胜  
2. `02-*` — 第二个 Part（通常是「写清楚」或「收口」）  
3. `03-*` — 把前两步的结果收成能拿出去的东西  

没有 `drills/` 的手册不算交付，只是说明书。

## 和 Skill 的关系

- `pack-howto`（或包根 `HOWTO.md`）是 **Part 0**，不是附录。  
- 其它 Skill 的 `SKILL.md` 可以短，细节指向手册第 5 节。  
- 用户永远先学手册，再碰到单个 Skill 名。
