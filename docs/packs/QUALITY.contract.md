# 场景包：好用门槛与升级

卖的是「装上就能做成一件岗位上的事」，不是 Skill 清单。
手册解决开口；这一页解决 **能不能卖、卖了怎么改**。

## 1. 「好用」只认四个结果

用户买了包、只装了 AI IDE 时，必须同时成立：

| 结果 | 通过线 | 不通过（不准上架） |
|---|---|---|
| 十分钟第一胜 | 冷用户照 `HOWTO` 第 2 节 + `drills/01` 能出约定交付物 | 只会聊天建议、要先学命令 |
| 三道练习能跑完 | 1→2→3 都有「成功长什么样」且对得上材料 | 练习 2/3 依赖未开通的 MCP |
| 装得上、卸得净 | `add-pack` 先计划再写盘；同名不覆盖；`remove-pack` 只删未改文件 | 覆盖用户已有目录、卸不干净 |
| 换包还会用 | 八节手册标题与上一包相同 | 每个包另发明一套学法 |

数字、人名必须来自 `drills/` 或用户材料。Agent 编出来的「好看结果」算失败。

## 2. 上架前五道门（和 skill-picker 门禁同一精神）

每道都要留下证据（录屏或对话导出 + 产物文件），缺一票否决。

| 门 | 查什么 | 谁过 |
|---|---|---|
| P0 作业完整 | 每个 Part 有一句「组合解决的问题」+ 成功形态；没有空 Part | 策展人 |
| P1 冷用户 | 找一个只装了 IDE、没听过 skill 的人，按手册做练习 1 | 该用户十分钟内出件 |
| P2 钉版本 | `pack.yaml` 每条 Skill/MCP **钉 commit**；许可证可再分发（MIT/Apache 等）；合集仓、awesome 不准进商品 | 清单审查 |
| P3 安装回滚 | 干净机器 `add-pack` 计划 → `--yes` → 练习 1 → `remove-pack` 磁盘回到装前 | 安装器测试 |
| P4 金样 | `drills/` 带期望要点（待办条数、禁止出现的词、必须出现的人名） | 自动或人工对照 |

P1 失败：改手册和例句，**先不要加 Skill**。
P0 失败：缺的 Part 要自研或从货架拿掉这个 SKU，禁止用无关 Skill 填数。

## 3. 完善（上架前怎么变好）

按失败原因改，禁止「再塞 10 个 GitHub」：

| 用户实际卡点 | 改哪里 |
|---|---|
| 不会开口 / 乱开口 | `HOWTO` 第 2–3 节 + 练习 1 的那句原话 |
| 出了件但对不上材料 | Skill 约束 + 金样；加「材料没有就写未知」 |
| 装上了第一步就要登录 | 把 MCP 挪到第 7 节；练习 1–3 必须零账号 |
| 同名冲突 / 卸不干净 | 安装器，不是再写一篇说明 |
| 某个 Part 没有候选 | 自研一条薄 Skill，或砍掉该 Part / 整个 SKU |

每个 SKU 只保留 **能覆盖作业链的最少 Skill**。多出来的进「可选」，不进默认安装。

## 4. 升级（卖了以后怎么改）

版本写在 `pack.yaml` 的 `version`，对用户只说人话。

| 变动 | 版本 | 对已购用户 |
|---|---|---|
| 修手册例句、修金样、修错字 | 补丁 | 提示更新手册；不重装 Skill 也可 |
| 换一条同职责 Skill、加一个可选 MCP | 次版本 | `add-pack` 出示计划：新增/替换/不动哪几条；同名仍阻塞 |
| 改岗位问题（「周报」变成「短视频」） | 主版本 | **新产品**，旧包继续能用，不强制迁移 |

禁止：浮动 `latest`、静默覆盖用户改过的文件、把失败 Part 用大杂烩仓补上。

每次发版必须带：

1. 「这次让哪一个结果更好了」（第一胜 / 练习 2 / 安装 / 开口）  
2. 冷用户再跑一遍练习 1 的证据  
3. 若有替换：旧 commit 留在 changelog，方便回滚

## 5. 卖之后看什么（没有这些数不要谈升级）

只看四条，都不需要读用户私人材料正文：

- **练习 1 完成率**（装包 24 小时内是否产出了约定形态）  
- **练习 1→3 做完人数**  
- **「不会用」售后占比**（开口问题归手册，装不上归安装器）  
- **回滚率**（`remove-pack` / 装了一半放弃）

练习 1 完成率低于一半：停售该版本，先改手册和金样，再考虑换 Skill。

## 6. 和五个主线包的关系

第 0 包（生活工作提效）是质量样板：P0–P4 先在它上面跑绿，其它包抄同一门禁。
底表拆出的 8 个货架包，没过 P1 冷用户的，只标「候选」，不上付款页。
从社媒笔记拆出这 8 包时，先走 `PACKAGING.workflow.md`，不要直接写 `pack.yaml`。
