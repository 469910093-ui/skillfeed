# 品牌令牌：取值依据与禁用清单

这份是**活文档**，描述当前生效的品牌色板与字体。
`docs/review/design-system-rules.md` 是某个时点的审计报告，记录的是审计当时的状态，两者冲突时以本文为准。

改动这些值之前请先读完「为什么中性灰不动」那一节，那是最容易好心改错的地方。

## 当前令牌

| 令牌 | 值 | 用途 | 实测对比度（`#fff` / `#fafafa`） |
|---|---|---|---|
| `--accent` | `#1e7362` | 全站唯一强调色：字标后半、链接、底部导航激活态、要点符号、focus 条 | 5.70 / 5.46 |
| `--accent-strong` | `#155246` | hover / press | 8.87 / 8.50 |
| `--ring` | `linear-gradient(135deg, var(--accent), #43a880)` | 头像环、story 环 | 非文本，无门槛 |
| `--like` | `#e0364f` | 仅「已赞 / 已存」的图标填充与背景 | 4.37 / 4.18（非文本 3:1 达标） |
| `--like-ink` | `#d6344c` | 同一红当**文本**用时的深一档 | 4.71 / 4.52 |
| `--link` | `var(--accent)` | 正文链接 | 同 accent |
| `--bg` | `#fafafa` | 壳内页面底 | — |
| `--ink` | `#262626` | 主文本 | 16.4 / 15.2 |
| `--muted` | `#737373` | 次要文本（承载「适合谁 / 为什么推荐」） | 4.74 / 4.54 |
| `--line` | `#dbdbdb` | 分隔线、描边 | 非文本 |
| `--font` | `Outfit` → `PingFang SC` → `Microsoft YaHei` | 全站正文 | — |
| `--logo` | `Outfit` 800 → `PingFang SC` | 字标 | — |

`--accent` 的 HSV 饱和度是 0.74，刻意压在 0.80 以下。选深青绿是为了同时离三样东西足够远：
Instagram 的暖色→洋红渐变、各类 AI 产品的紫、以及微信绿 `#07C160`（亮而高饱和）。

对比度不是估的，是按 WCAG 2.x 相对亮度实算的；`--muted` / `--link` / `--like-ink` 这三个值
是在各自色相与饱和度上**逐档降明度搜出来的「刚好过 AA 的最亮值」**，所以往亮的方向动一档就会掉出 AA：

- `--muted` `#737373` → 再亮一档 `#747474` 掉到 4.48
- `--like-ink` `#d6344c` → 再亮一档 `#d7344c` 掉到 4.49

`tests/test_feed_dashboard.py::TestContrastTokens` 会用真实数值复算，底色从 `--card` / `--bg`
令牌里读而不是写死，所以换底色也逃不掉这道门。

## 禁用清单：不许搬回来的 Instagram 品牌识别要素

`TestNoInstagramTradeDress` 断言这些值**不出现在页面外壳里**（`<style>` + head + 静态 markup）。

断言范围刻意剔掉了 `<script>` 里的内容数据：feed 里本来就有正当提到 Instagram 的条目
（`instagram-curator`、"TikTok and Instagram carousel" 之类）。对整页 HTML 做字符串断言
会在空 feed 下是绿的、一有真实内容就炸，属于最难查的那种假绿——测试里专门放了一条
提到 Instagram 的夹具条目来证明不会误报。同理，源码 docstring 里提到这些值是文档，不算违规。

| 禁用 | 是什么 |
|---|---|
| `Billabong` | Instagram 字标本身用的字体。风险最高的一项 |
| `#f09433` `#e6683c` `#dc2743` `#cc2366` `#bc1888` | 那条 5 段暖色→洋红渐变，IG 最可识别的品牌资产 |
| `#ed4956` | IG 的点赞红 |
| `#00376b` | IG 的链接蓝 |
| 页面上出现 "Instagram" 字样 | 自称照抄是意图的书面证据，比色值更难解释 |

**「手写体字标 + 渐变填充」这个组合是重点**。单换字体或单换渐变都不够——让人一眼把页面
认成 Instagram 的是这个组合，而且原先那条渐变同时铺在字标和**每张卡片的头像环**上，
曝光面是整个信息流。所以字标现在是 Outfit 800 的实心字，`.logo` 上不再有 `background-clip: text`。

关于 `Billabong` 还有个事实值得记一下：**它根本不在 Google Fonts 上**，原来那行
`family=Billabong` 一直是空转。实测加与不加，`fonts.googleapis.com/css2` 返回的都是
同样的 3724 字节 / 9 个 `@font-face`（Google Fonts 对未知 family 是静默忽略，不是返回 400）。
所以实际渲染的一直是 `Cookie`，那个手写体。

## 为什么中性灰刻意不动

`--bg: #fafafa`、`--ink: #262626`、`--line: #dbdbdb` 这几个值确实也是从 Instagram 那边来的，
但它们**保持不变**，理由是：

1. 浅灰不构成任何人的品牌识别。几千个站点在用同一批中性值，没人拥有它们。
2. 挪到 `#f5f6f7` 这种量级的位移（RGB 曼哈顿距离 8~18）肉眼看不出差别，
   法律上也不减少任何风险，只会让上面那张表里的实测比值全部作废、并在 diff 里制造噪音。
   这是「看着像修了、其实什么都没变」的改动。
3. 要换就得换出可感知的差别（比如整体转冷或转暖一档），那是一个独立的品牌决定，
   需要连带重算所有文本令牌的对比度，不该混在拆商标风险这件事里做。

## 已知的遗留问题

- `fonts.googleapis.com` 在国内不可达，Outfit 会回退到 `PingFang SC`。
  字标改用 Outfit 800 之后这件事的后果轻了（回退后仍是个粗体字标，
  而不是原来那样退化成系统 `cursive`），但正文字形在国内仍与设计稿不一致。
  彻底解决要自托管字体子集，那会改动构建产物，是独立的一件事。
- `.act.saved`（收藏）目前和 `.act.liked`（点赞）共用 `--like`，视觉上两个信号分不开。
  这是「点赞与收藏同一信号」那条待办的一部分，属于语义问题，不在色板范围内。
